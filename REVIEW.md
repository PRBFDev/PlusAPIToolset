# Ревью PlusAPIToolset

Исходная версия: commit `0134282`, локальный репозиторий, 21 октября 2026.
Оценка основана на исходниках и локальной сборке. Игра в рамках ревью не запускалась.
Происхождение кода, использование Gemini и заявленный стаж автора не проверялись.

## Оценка

Проект выглядит как работающий по компиляции прототип API, которому нужна
проверка поведения в игре и доработка контрактов. В этой версии код не демонстрирует
качество готовой библиотеки уровня senior: есть ошибки идентификации владельца
ресурсов, потенциальная блокировка игрового потока и небезопасная совместимость
с другими модами. По одному небольшому репозиторию нельзя установить общий
уровень разработчика или опровергнуть его стаж. Сам факт использования ИИ ничего
не говорит о качестве; значение имеют проверенные результаты.

Хорошие решения: отдельные типы для описания соды и фабрик, флаги этажей,
отложенная регистрация до появления исходного BSODA, защита от повторного
добавления того же предмета в массивы генерации. Это полезные заготовки API.

## Существенные проблемы, оставшиеся после очистки

### P1 — ожидание аудио блокирует вызывающий поток

`BsodaToolkit/SodaBuilder.cs`, метод `LoadAudio`: после `SendWebRequest()` стоит
пустой `while (!req.isDone)`. При загрузке ресурса из обычных Unity-колбэков это
блокирует главный поток и расходует CPU. При зависшем запросе выход не ограничен
таймаутом. Это риск фриза, а не доказанный в этом ревью дедлок.
Нужно загружать звук корутиной и регистрировать предмет после завершения загрузки;
синхронный контракт регистрации следует менять согласованно с потребителями API.

### P1 — GUID плагина ищется на сборке вместо класса

`BsodaToolkit/SodaObject.cs`, свойство `ModGuid`, и `SodaBuilder.AutoRegisterAll`
вызывают `Assembly.GetCustomAttribute<BepInPlugin>()`. В этом же проекте
`BepInPlugin` установлен на классе `PluginInitializer`, а не на сборке.
При обычном оформлении внешнего плагина код получает `null` и использует GUID
самой библиотеки. Ресурсы ищутся в чужой папке, а владельцем метаданных становится
не тот мод. Нужно передавать владельца при регистрации или брать его из
`Chainloader.PluginInfos`. Для нескольких плагинов в одной сборке необходим
явный выбор владельца. Переопределение `ModGuid` сейчас служит обходным решением.

### P1 — резервная регистрация предметов допускает коллизии

`Core/ItemEnumExtensions.cs` выдаёт ID, начиная с `1000`, без координации с другими
модами. `SodaObject.ItemType` передаёт только `GetType().Name`: два разных типа
`SomeMod.TestSoda` и `OtherMod.TestSoda` получат один ключ и один ID. При переходе
между сессиями ID зависит от порядка регистрации. Нужен общий реестр и ключ
из GUID владельца и полного имени типа; совместимость сохранений требует
отдельного решения. Добавленное логирование делает ошибки MTM101 видимыми,
но не устраняет сам риск резервного алгоритма.

### P2 — очистка эффектов привязана только к истечению таймера

`BsodaToolkit/SodaObject.cs`: удаление `moveMod` происходит в `OnTimeExpired`
и при выходе из триггера. Если другой мод уничтожит снаряд раньше таймера,
отдельного `OnDestroy` для снятия эффектов нет. Повторный вход того же объекта
также добавляет модификатор повторно. Нужны идемпотентная очистка при уничтожении
и определённое поведение при нескольких коллайдерах одной сущности.

### P2 — глобальный патч скрывает ошибки и меняет все Entity

`Core/HarmonyBuilder.cs`, `EntityUpdatePatch`: пропускается весь `Entity.Update`
для любой сущности без `Ec`. Патч не ограничен префабами библиотеки. Если это
обход ошибки инициализации собственных префабов, нужно исправить их жизненный
цикл или сузить условие. Влияние на чужие сущности требует проверки в игре.

## Сопровождение

`SodaBuilder` содержит около тысячи строк: поиск ресурсов, декодирование WAV,
reflection-интеграции, создание префабов, регистрацию и генерацию уровней.
Выделение загрузчика ресурсов и адаптера MTM101 позволит проверять эти части
отдельно. Автоматических тестов в исходной версии нет; пример `TestSoda`
не заменяет проверку поведения. Парсер WAV, в частности, не учитывает выравнивание
RIFF-чанков нечётной длины (`pos += chunkSize`).

## Что исправлено при очистке

- Удалены шесть старых `.bak`; новые резервные файлы исключены из Git.
- Вместо 107 прямых ссылок оставлены 10 необходимых для текущей компиляции.
- Путь к игре вынесен в игнорируемый `GamePath.user.props`; добавлен пример.
- Запрещено копирование игровых зависимостей в папку готового плагина.
- `TestSoda` исключён из обычной сборки; доступен через `IncludeExamples=true`.
- Добавлена отписка `PlusAssetsManager` от события смены сцен при уничтожении.
- Кеш `ObjectToolkit` перепроверяет уничтоженные Unity-объекты.
- Нулевой quaternion при `Spawn` заменяется на `Quaternion.identity`.
- Поиск спрайта включает неактивные дочерние объекты префаба.
- Ключи кеша ресурсов учитывают GUID, сборку типа и масштаб спрайта.
- Embedded-ресурсы читаются до конца, а не одним вызовом `Stream.Read`.
- Скрытые исключения загрузки и интеграции записываются в журнал.

Эти исправления сохраняют публичные сигнатуры API. Исключение примера из обычной
DLL — намеренное изменение состава сборки. Выше перечисленные P1/P2 остаются
открытыми; очистка не является заявлением о готовности API к релизу.

## Проверки после изменений

- После `dotnet clean` выполнены Debug и Release: 0 ошибок, 0 предупреждений.
- Сборка с `IncludeExamples=true` также проходит без ошибок и предупреждений.
- Метаданные DLL проверены без загрузки Unity: в обычном Release нет `TestSoda`,
  в отдельной сборке примера он присутствует.
- Проверен неверный `GamePath`: сборка завершается с сообщением `Missing dependency`
  и путём недостающего файла.
- В обычной папке Debug остаются только DLL, PDB и deps.json самой библиотеки.
- `git diff --check` не выявил ошибок пробелов.

Это проверки сборки и состава артефактов. Поведенческие тесты Unity не выполнялись;
изменения жизненного цикла и ресурсов нужно проверить в игровом запуске.
